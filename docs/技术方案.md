# BrowserPilot 技术方案

同一个 Electron 应用里可以开多扇窗口。人和 Agent 看的是这些窗口里的标签。技术栈和仓库拆法对齐 TermPilot：主进程提供 MCP，Go 命令行走同一份工具定义。

页面放在窗口内的 `WebContentsView` 里。不另开 Clearcote，也不编译 Chromium。多扇窗口仍是这一个进程，不是每个窗口再启动一份 BrowserPilot。

## 技术栈

| 层 | 选型 |
|---|---|
| 壳 | Electron 44、electron-vite、electron-builder |
| 界面 | React 19、TypeScript、Tailwind 4、shadcn |
| 状态 | zustand，放主进程能碰到的数据以主进程为准 |
| 工具定义 | `src/main/services/tool-catalog.ts`，zod 描述参数 |
| MCP | `@modelcontextprotocol/sdk`，Streamable HTTP，只绑 `127.0.0.1`，Bearer |
| 命令行 | Go：`browserpilot tools` / `schema` / `call` |
| 页面视图 | 每个标签一个 `WebContentsView` |
| 会话 | 每套环境一个 `persist:` 分区，登录态留在本机用户目录 |

端点文件：`%APPDATA%\BrowserPilot\mcp.json`。命令行自己读，令牌不进对话。应用没开时，命令行先启动 BrowserPilot，再把调用送进这一个进程。MCP 只有一份，不随窗口变多。

## 进程

```text
Agent 或 browserpilot 命令
        │  127.0.0.1 + Bearer
        ▼
Electron 主进程（一份）
  tool-catalog     MCP 和命令行共用
  EnvService       env- ↔ persist 分区，每套最多一扇窗口
  TabService       标签 ↔ WebContentsView，跟着所在窗口的环境
  RecordService    录制、回放、批量
  NetService       单个标签的 HTTP 记录
        │
        ▼
多扇 React 窗口，同一进程
  每扇：标签栏 + 工具栏 + 整页内容。设置从工具栏右侧的菜单打开
        │
        ▼
该标签的 webContents
  点击、输入、粘贴、选择：via 为 cdp（默认）、native 或 inject。滚动、滑动、按键：via 为 cdp（默认）或 native
  截图：capturePage
  无障碍树、抓包体：webContents.debugger（CDP），用完即 detach
```

渲染进程不直接碰网页 DOM。它通过 IPC 让主进程操作当前标签。

## 窗口里有什么

窗口布局和普通浏览器一样。组件用 shadcn，标签栏和工具栏按浏览器来画。标签默认排在顶部。

```text
[ 网页标签 ] [ 网页标签 ] [ 设置 ] [ + ]
[ ←  →  ↻   地址栏                          菜单 ]
[ 整页内容                                              ]
```

通用里可以把标签改到左侧，竖着排。左侧默认收成窄栏，鼠标靠近就盖在网页上展开，离开就收回，网页区域不动。点窄栏顶部的固定后，这一列才占住左边，网页跟着让开。再点一次取消固定。地址栏仍在上面。右键、分组、复制标签信息都还在。

```text
[ ←  →  ↻   地址栏                          菜单 ]
[ 网页标签 ][ 整页内容                              ]
[ 网页标签 ]
[ 设置     ]
[ +        ]
```

这一扇窗口里的标签都属于同一套环境，标签上不再单独标环境。右键某个标签可以「复制标签信息」：剪贴板里是这个 `tab-`、标题、URL 和所属 `env-`。Agent 拿到之后只传 `tab-` 就能操作这一页。

同一条标签栏里可以把标签收成组。一组有名称和颜色，编号是 `grp-`。组只存在于这一扇窗口里。拖进一组或从菜单里选「加入分组」。新建用 `group_create`，改名称或颜色用 `group_update`，编号不变。把标签放进组或移出用 `tab_group`。

网页标签在顶部时，地址栏在标签下面。改成垂直之后，地址栏在最上面，标签在页面左侧，平时只留一条窄栏。鼠标靠近时标签栏盖住网页展开，离开后收回，不改网页宽度。只有点顶部的固定，左侧才占位，网页内容区跟着变窄。切走时 `WebContentsView` 藏起来，不销毁，登录态还在。

窗口自己处理下面这些快捷键，人在键盘上按下时生效。焦点在网页里时也要先被窗口接到，不能送给页面。Agent 不靠模拟这组按键来操作窗口：新建标签用 `tab_open`，刷新用 `page_reload`，关闭用 `tab_close`。

| 快捷键 | 作用 |
|---|---|
| `Ctrl+T` | 在当前窗口里新建标签，仍用这一套环境 |
| `Ctrl+W` | 关闭当前标签 |
| `Ctrl+Shift+T` | 重新打开刚关掉的标签 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 下一个 / 上一个标签 |
| `Ctrl+1` … `Ctrl+8` | 切到第几个标签 |
| `Ctrl+9` | 切到最后一个标签 |
| `Alt+Left` / `Alt+Right` | 后退 / 前进 |
| `F5` / `Ctrl+R` | 刷新 |
| `Esc` | 停止加载 |
| `Ctrl+L` / `Alt+D` | 聚焦地址栏 |
| `Ctrl+F` | 在当前页查找 |
| `Ctrl+Plus` / `Ctrl+Minus` / `Ctrl+0` | 放大、缩小、恢复缩放 |
| `F11` | 全屏 |

书签、扩展、无痕窗口没有对应功能，就不做那些快捷键。页面自己的快捷键仍由网页接收。

工具栏最右侧是一个菜单按钮。点开后在按钮下面展开。菜单画在网页视图上面，不会被页面挡住。

| 菜单项 | 作用 |
|---|---|
| 新创建窗口 | 再开一套环境，窗口直接显示。编号自动分配，仍在这一个进程里 |
| 复制环境编号 | 复制这扇窗口的 `env-`，交给 Agent 指定登录态 |
| 开发者工具 | 打开当前网页标签的 DevTools |
| 开始录屏 | 把这扇有头窗口的画面录成 MP4，用来做教程。正在录时这一项变成「停止录屏」 |
| 设置 | 在网页区域打开内置页面 |
| 关于 | 同一设置窗口里的关于 |

系统标题栏不显示。顶部标签栏自己画，右侧是最小化、最大化和关闭，空白处可以拖动窗口。任务栏和切换窗口时仍显示这套环境的名称。标签上的关闭按钮一直显示。

设置从菜单打开，直接画在窗口的内容区里，占一个标签。地址栏写「设置」。切到普通网页标签时，这一块再交给 `WebContentsView`。左侧是导航，右侧是内容：

`环境` · `工作流` · `抓包` · `通用` · `关于`

环境这一格列出当前保存的每一套（名称、备注、编号）。一套里面可以有很多个网站的登录，不是一个网站一套。点开一套，下面按网站列出：域名、Cookie 还在不在、最近一次打开的时间。Cookie 的值不显示。登录与否用来自该分区的 Cookie 域名判断，不额外去访问这些网站。

这里可以新建一套。新建会分配一个新的 `env-`，并在同一个应用里再开一扇看得到的窗口，不是再启动一个进程。人在菜单或设置里新建、打开，都是有头。也可以选一套已经存在的，把它的窗口显示出来；这套已经开着时，只把窗口带到前面，不另开一扇。关掉窗口不清登录。每套都可以改名称、改备注。除了 `env-default`，其余可以删除。

工作流这一格是已保存的图。点一条在内容区打开画布，地址栏写工作流名称。切回普通网页时再显示网页视图。节点从左向右排。左边端点是进入，右边端点是出去。判断节点右边每个分支一个端点，都不成立走 ELSE。循环双击进入内部。拖端点连线，点节点后在右侧改内容。Agent 不在图上点，仍用 `workflow_run` 一次跑完。同一条上可以填参数后自己执行，也可以把说明复制给 Agent。地址栏左边的「市场」也直接画在窗口内容区里，和设置同一套界面组件。切到普通网页时再显示网页视图。目录每次都向 GitHub 仓库 `xy200303/browserpilot-market` 读取，不使用安装包里的副本。也可以粘贴一份 GitHub 上的 JSON 地址。下载后写入本机，同名覆盖。抓包这一格是当前网页标签上的请求。通用这一格放标签栏位置（顶部或左侧）、MCP 开关、端口、批量并发上限，以及同时开着的无头窗口上限。

编号规则和 TermPilot 一样，只拿编号当参数：

| 前缀 | 是什么 |
|---|---|
| `env-` | 一套环境。里面是多个网站的登录，对应最多一扇窗口。不传时用 `env-default` |
| `tab-` | 标签。所有窗口里的编号全局唯一，关掉之后不把这个编号发给新标签。属于所在窗口的那一套环境，不能换到另一扇窗口的环境里。可以放进一个 `grp-`。只传这个编号就能找到它，不必再传 `env-` |
| `grp-` | 标签分组。只影响这一扇窗口的标签栏 |
| `wf-` | 一份工作流 |
| `req-` | 一条抓到的请求 |

## 操作页面

找元素用 CDP 的无障碍树。点击、输入、粘贴、选择的 `via` 有三种，默认 `cdp`。滚动、滑动、按键默认也走 CDP 的 `Input` 域，`via` 为 `native` 时改用 `sendInputEvent`。截图用视图自己的画面。

- `cdp`：调试协议的 `Input` 域，事件 `isTrusted` 为 true。点击是 `Input.dispatchMouseEvent`（`mouseMoved`、`mousePressed`、`mouseReleased`），坐标是视口 CSS 像素，按这个点做命中测试。输入是 `DOM.focus` 之后逐键 `Input.dispatchKeyEvent`，非拉丁字符用 `Input.insertText`。粘贴是聚焦后整段 `Input.insertText`，不经过剪贴板。
- `native`：`webContents.sendInputEvent`。点击是移动、按下、松开。输入是逐键 `char`。粘贴是写入系统剪贴板再发 `Ctrl+V`。同样是可信输入，点不到被挡住的位置会失败。
- `inject`：在目标元素上派发指针和输入事件，写法参考 page-agent。`isTrusted` 为 false，不经过命中测试，被挡住也能作用在这个节点上。只在明确传入时使用。

`page_script` 用来在当前网页里执行一段 JavaScript。主进程用 `executeJavaScript` 跑传入的源码，把返回值交回。单次最长 120 秒。要把表写成 CSV，用工作流里的 `export` 节点。

| 动作 | 工具 | 怎么做 |
|---|---|---|
| 打开、后退、前进、刷新 | `page_navigate` / `page_back` / `page_forward` / `page_reload` | `loadURL`、`navigationHistory`、`reload` |
| 点击 | `page_click` | `via` 默认 `cdp`，用 `Input.dispatchMouseEvent`。`native` 用 `sendInputEvent`。这两种只点能命中的位置。`inject` 在节点上派发事件再 `click()`。定位用 `xpath` 或 `selector`，原样交给浏览器，必须恰好一个。元素有一部分在画面外时，先把它滚进画面，再点能命中的位置。画布没有稳定节点时改用 `x` 和 `y`：不带截图宽高时是当前视口的 CSS 像素；带上 `page_screenshot` 返回的 `shotWidth` 和 `shotHeight` 时，是这张图上的像素，先换算到视口再点。多个匹配用 `page_query` 取数组。`until` 是点完后要出现的元素，没出现就在同一个定位上再点，最多 3 次。失败时带上匹配个数、文字和当时能不能点到 |
| 输入 | `page_type` | 先按 `xpath` 或 `selector` 找到元素。`cdp` 聚焦后逐键下发，非拉丁字符用 `Input.insertText`。`native` 先真实点击再逐键输入。`inject` 写入输入框或可编辑区域；页面有 CKEditor 时用 `setData` |
| 粘贴 | `page_paste` | `inject` 直接写入目标，iframe 和重试与输入相同。`cdp` 聚焦后 `Input.insertText`。`native` 写入系统剪贴板再发送粘贴快捷键 |
| 选择 | `page_select` | `inject` 对 `<select>` 直接改值并派发 `change`；自定义列表则注入点击打开再点选项。`cdp` 和 `native` 都是打开后再点那一项，分别走 CDP 鼠标和真实鼠标 |
| 按键 | `page_key` | `via` 默认 `cdp`，用 `Input.dispatchKeyEvent`。`native` 用 `sendInputEvent`。`shortcut` 写成 `Enter`、`Tab`、`Escape`、`Ctrl+A`、`Ctrl+Shift+Enter` 这种形式 |
| 滚动 | `page_scroll` | 翻长列表用滚动。`via` 默认 `cdp`，用滚轮事件。`native` 用 `sendInputEvent`。不指定元素时从视口中心滚一下。`until` 表示滚到该元素能被点到：先滚进视口，再用页面命中确认没有被顶栏挡住，最多 16 次。失败时带上匹配个数、文字和当时能不能点到 |
| 滑动 | `page_swipe` | 按住拖拽，用来拖滑块或横滑一块区域。翻长列表用滚动。`via` 默认 `cdp`，同一次手势的按下、移动、松开。`native` 用 `sendInputEvent`。不指定元素时从视口中心滑。指定元素时只用它此刻露在视口里的那一块，手势停在这块区域里面。`until` 同样用 `xpath` 或 `selector`，表示滑到该元素在视口里能被点到，最多 20 次 |
| 上传 | `page_upload` | CDP 把本机文件路径交给页面上的文件控件，不弹出系统选择框 |
| 读文字 | `page_snapshot` | 无障碍树里的名字和值 |
| 截图 | `page_screenshot` | `capturePage`。命令行只返回本机图片路径 |
| 源码 | `page_source` | CDP 读取。`dom` 是当前文档；`response` 是这次导航拿到的原始 HTML |

长流程由这些动作串成一张图，放在一次 `workflow_run` 里做完。发一篇文章就是：打开后台、点写文章、输入标题、粘贴正文、把封面放上去、选择分类、滚到发布按钮、点击发布。封面怎么放，看这个后台：有的是把本机文件交给上传控件，有的是往输入框里填一个图片链接。中间不把每一步交回给 Agent。

很多后台是单页应用。地址加载完成时，正文往往还没画出来；点「写文章」也常常不换文档，只是后面再渲染出一块新界面。找元素看的是此刻的文档，不看这次导航最初的 HTML。`page_source` 的 `response` 经常只有空壳，当前画面用 `page_snapshot` 或 `kind: dom`。

快照不是整页 HTML，只保留读屏软件能看到的节点：角色、名字、值。点击和输入不拿快照里的文字去对，而是用 XPath 或 CSS 选择器重新找元素。XPath 原样交给 `DOM.performSearch`，选择器原样交给 `DOM.querySelectorAll`。要第几个，把下标写进 XPath，例如 `(//li[contains(@class,'job-card-box')])[1]`。快照编号会随刷新失效，不作为定位。画布上的点用截图坐标，并带上这张图的宽高。

```text
- heading "订单"
- textbox "单号"
- button "查询"
```

## 锁定

Agent 正在操作某张网页标签时，页面上弹出遮罩。正中文字是「Agent 正在操作浏览器」，下面一个「接管」按钮。遮罩挡住鼠标和键盘，用户这时不能点页面。单次和批量都这样。任务不会因为这个按钮停掉。

用户点「接管」之后，遮罩去掉，用户可以操作这个页面。Agent 的任务继续执行，不暂停。从这一刻起，Agent 和用户同时操作同一张网页。后面的步骤、还没开始的批量行都照常进行。

每个工具的返回里都带 `control`，Agent 靠这个知道页面是不是被人动过，而不是看到界面变了却不知道原因：

| `control` | 含义 |
|---|---|
| `agent` | 遮罩还在，只有 Agent 在操作 |
| `shared` | 用户已点「接管」，或 Agent 已调用 `page_unlock`。两边同时操作 |
| `handoff` | 正在等用户完成 `page_handoff` 的那一步 |

一次 `workflow_run` 里如果用户点过「接管」，这次调用的返回里 `control` 为 `shared`，并带 `takenOver: true`。Agent 据此重新 `page_snapshot` 再决定下一步，不把中途的变化当成自己点错。

Agent 也可以自己调用 `page_unlock` 去掉遮罩，效果和用户点「接管」相同：用户可以操作，任务不暂停，两边同时操作，之后的工具返回 `control: "shared"`。

遇到需要用户自己做的步骤，例如输入密码或滑动验证码，Agent 或脚本用 `page_handoff` 标出来，并带上提醒。执行到这一步时遮罩自动去掉，窗口里留下这句提醒，这段时间 `control` 为 `handoff`。这扇窗口如果当时是无头的，先显示出来，人才能操作。用户做完后，不用再点开始：下一步的目标一出现，就重新盖上遮罩，`control` 回到 `agent`，从下一步继续。

锁定只影响这一张标签。

## 不暴露自动化属性

页面上不要出现「这是自动化浏览器」的标记。做法是不打上这些标记，而不是再注入一段脚本去改它们。

- 启动参数里不要带 `--enable-automation`。`navigator.webdriver` 保持 `false`。
- 用户代理用与这份 Electron 所带 Chromium 同版本的 Chrome 标识，去掉 `Electron` 和 `HeadlessChrome`。
- 不给网页视图挂预加载脚本。默认的点击、输入、粘贴、选择、滚动、滑动、按键走 CDP 的 `Input` 域，不调用 `executeJavaScript`。
- `page_script`，以及显式 `via: 'inject'` 的点击、输入、粘贴、选择，才会在页面里执行脚本。
- 无障碍树、上传、抓包和 `page_cdp` 需要调试器时，用完立即 `detach`，不在页面里留绑定对象。
- 窗口用正常的可见尺寸，不用自动化工具常见的默认视口。无头只是创建窗口时不显示，视口仍是这个尺寸，用户代理里仍然不要出现 `HeadlessChrome`。

这只去掉我们自己会加上的自动化标记。它不是另一套改过指纹的浏览器引擎。

## 环境

环境用来隔开登录。一套环境里可以同时留下很多个网站的 Cookie，例如公众号、后台和邮箱各登各的。不同的 `env-` 互不可见。步骤和脚本不绑在某一套上。

一扇窗口就是一套环境，这扇窗口里的每个标签都用它。不能在同一扇窗口里混进另一套的标签。

第一次启动打开一扇窗口，编号固定为 `env-default`，名称一开始是「默认」。名称和备注可以改，编号不变，这一套不能删除。下面这些工具不传 `env` 时，都用它这扇窗口：

`tab_open`、`workflow_write`、`workflow_update`、`workflow_run`、`workflow_batch`、`workflow_export`、`workflow_import`

要换一套登录，传入另一个 `env-`。窗口没开就先在这个进程里打开它，再操作。同一套不会开出第二扇窗口。

人新建或打开的窗口一定显示在桌面上。无头只给 Agent 用：对一套已经存在的环境调用 `env_open({ headless: true })`，窗口不显示，点击、截图、回放仍用同一套工具。适合一次跑很多个账号，每个账号一扇无头窗口。无头不是换一套带 `HeadlessChrome` 的浏览器，只是这扇窗口 `show: false`。需要人输入密码或验证时，`page_handoff` 会先把这扇窗口显示出来。

同时开着的无头窗口数量由设置封顶，默认最多 3。超出时这次打开失败，已经在跑的不打断。有头不占这个数量。第一次启动的默认窗口是有头。

一套环境是一个 Electron 持久分区：`session.fromPartition('persist:' + id)`。Cookie、localStorage、登录会话写在本机用户目录里。关掉窗口再打开，登录还在。

```ts
tab_open({ url: 'https://mp.weixin.qq.com/' })
// 不传 env，落在 env-default 的窗口

env_create({ name: '账号-甲', remark: '主号' })
// 分配 env-...，窗口显示出来

env_open({ env: 'env-...', headless: true })
// 同一套已有登录，批量时不显示窗口。人要看时 headless 传 false

tab_open({ url: 'https://mp.weixin.qq.com/', env: 'env-...' })
tab_open({ url: 'https://mail.example/', env: 'env-...' })
// 两个网站的登录都在这一套里，标签都在它的窗口中
```

人在这扇窗口的标签里登录。之后不传 `env` 仍是默认那套；传入 `env-...` 才是这一套。工具栏菜单里可以复制这个编号，Agent 用它指定要操作哪一扇。`env_list` 返回编号、名称、备注、窗口是否开着、当前是有头还是无头，并标明哪一套是默认。不返回 Cookie。

名称和备注用 `env_update` 改，编号不变。删掉一套用 `env_delete`：关掉它的窗口，分区里的 Cookie 和登录一并清掉。`env-default` 不能删。只想收起窗口时关掉窗口即可，环境还在，设置里可以再打开。

## 录屏

录屏记的是这扇窗口的画面，用来做教程。和下面的脚本录制不是一回事：脚本记的是 Agent 的工具调用，录屏记的是人眼看到的操作过程。

从菜单点「开始录屏」，或由 Agent 调用 `screen_start`。录的是整扇窗口，包含标签栏、地址栏和网页。标签在左侧时，左侧这一列也在画面里。工具栏上有正在录制的标记。再点「停止录屏」或调用 `screen_stop`，写成一个 `.mp4` 文件，放在本机用户目录，工具返回这个路径。不往页面里注入脚本。

只录有头窗口。无头没有可看的画面，调用会失败，先有头打开再录。一扇窗口同时只录一段。

## 工作流

工作流是 Agent 写下来的一张图，不是人在页面上的鼠标轨迹，也不往页面里注入脚本。要留一份能看的教程视频，用上一节的录屏。

第一次做「微信公众号发文章」时，Agent 仍要一步步 `page_snapshot`、`page_click`、`page_type`。做通之后，Agent 用 `workflow_write` 写入一张 Dify 形态的图：`nodes` 和 `edges`，没有步骤数组。之后发文章只调用一次 `workflow_run`，传入开始节点声明的输入。主进程顺着边跑完，不再把每个节点交回给 Agent。

### 记下来的是什么

图由 `workflow_write` 整份写入。没有开始录制，页面操作也不会自动记进草稿。同名再次写入时覆盖这张图，编号不变。只改几个节点、连线、名称或说明时用 `workflow_update`，没写到的部分保持原样。节点按编号替换；新编号追加到最外层，写了 `parent` 就放进那个循环。`removeNodes` 删掉节点和连着它的线。连线按两端所在的那一层替换或追加。

存储和 `workflow_export` 导出的文件是 JSON：`kind`、`version`、`app.mode` 为 `workflow`、`workflow.graph.nodes`、`workflow.graph.edges`。导出文件放在本机 `exports`，扩展名是 `.json`。

变量按选择器取，选择器是字符串数组，至少两段。`["input", "标题"]` 是这次运行的输入。`["sys", "url"]`、`["sys", "title"]`、`["sys", "tabId"]`、`["sys", "env"]` 是当前标签，只读。`["env", "名字"]` 是工作流上的 `environment_variables`。`["节点编号", "字段"]` 是那个节点的产出。文本字段里插值写成 `{{#节点.字段#}}`，只出现在地址、正文、请求头、定位字符串这类文本里。结构化输入写成 `value_selector`，不把整份数据先变成字符串。

开始节点 `data.type` 为 `start`，`variables` 里每一项有 `variable`、`label`、`type`（`text-input` 或 `number`）、`required`。结束节点 `end` 的 `outputs` 是 `{ variable, value_selector }`。判断节点 `if-else` 的 `cases` 里有 `case_id` 和 `conditions`。条件的 `comparison_operator` 可以是 `contains`、`is`、`empty`、`not empty`，取值用 `variable_selector` 和 `value`。`locator` 表示页面上有这个元素，默认等 3 秒，元素没出现只是这条条件不成立。成立的边 `sourceHandle` 用这个 `case_id`，否则用 `false`。

浏览器节点的 `data.type` 是 `goto`、`click`、`fill`、`select`、`press`、`scroll`、`swipe`、`upload`、`handoff`、`script`、`cdp`。定位写在 `locator` 里，只有 `xpath` 和 `selector`。`xpath` 以 `/` 开头，整段交给 `DOM.performSearch`。`selector` 整段交给 `DOM.querySelectorAll`。点击、填写、选择必须恰好匹配一个。匹配到多个就停在这个节点，不取第一条。`fill` 把文字写进控件，`entry` 为 `type` 时逐字输入，为 `paste` 时整段贴入。`script` 在当前网页里跑 JavaScript，能用页面和这次登录；`code` 在主进程里跑独立脚本，只看得到声明的输入，碰不到页面。两边都用 `inputs`，都必须 `return` 一个对象；写了 `outputs` 时，缺字段或类型不对就失败。`http-request` 在当前网页里发请求，产出 `status_code`、`body`，正文能解析成 JSON 时还有 `json`。`extract` 用 `variable_selector`、`pattern`、`flags`、`group` 做正则，产出 `value` 和 `matches`。`loop` 的 `mode` 为 `list` 时按 `items_selector` 逐项跑内部的 `nodes` 和 `edges`，当前项在 `["loop","item"]`，序号在 `["loop","index"]`；`mode` 为 `until` 时重复到 `until` 成立，默认最多 40 次，到了还没成立就失败。每轮产出收进这个节点的 `output`。`export` 可以接 `data_selector` 指向 `{ filename, headers, rows }`，也可以分开写 `filename`、`headers` 或 `headers_selector`、`rows_selector`。CSV 放进这次结果的 `files`，节点自己的产出是 `path`。没有结束节点时，最后一次产出直接作为这次运行的 `outputs`。

一张图只有一个开始节点。节点编号不能重复。一条边上的 `source` 和 `target` 必须是图里的节点。节点不能被走到两次，所以图不能成环，也不能两条边汇到同一个节点。

```ts
workflow_write({
  app: { name: '公众号发文章', description: '', mode: 'workflow' },
  workflow: {
    graph: {
      nodes: [
        { id: 'start', data: { type: 'start', title: '开始', variables: [
          { variable: '标题', label: '标题', type: 'text-input', required: true },
          { variable: '正文', label: '正文', type: 'text-input', required: true },
          { variable: '封面', label: '封面', type: 'text-input', required: true }
        ] } },
        { id: 'open', data: { type: 'goto', title: '打开后台', url: 'https://mp.weixin.qq.com/' } },
        { id: 'title', data: { type: 'fill', title: '标题', entry: 'paste', locator: { selector: '#title' }, text: '{{#input.标题#}}' } },
        { id: 'body', data: { type: 'fill', title: '正文', entry: 'paste', locator: { xpath: "//div[@contenteditable='true']" }, text: '{{#input.正文#}}' } },
        { id: 'cover', data: { type: 'upload', title: '封面', locator: { selector: 'input[type="file"]' }, paths: ['{{#input.封面#}}'] } },
        { id: 'publish', data: { type: 'click', title: '发表', locator: { xpath: "//button[@id='publish']" } } }
      ],
      edges: [
        { source: 'start', target: 'open' },
        { source: 'open', target: 'title' },
        { source: 'title', target: 'body' },
        { source: 'body', target: 'cover' },
        { source: 'cover', target: 'publish' }
      ]
    }
  }
})
```

工作流写在本机用户目录的 `workflows.json`，重启后还在。图里不写环境编号，跑的时候再传 `env`。设置页的「工作流」一格列出名称和参数名，点一条在内容区打开画布。关掉这页回到旁边的标签。普通节点左右各一个端点。判断节点的每个 `case_id` 是一个输出端点，`false` 是 ELSE。循环点进去编辑内部的节点和连线。拖动、连线、改节点都通过 `workflow_update` 写回，编号不变。每条可以导出 JSON，顶部可以导入一份 JSON。同名导入覆盖原来的图，编号不变。不上传。`workflow_export` 把图写到本机 `exports`，`workflow_import` 从本机路径读回来。市场只从 GitHub 下载 JSON，不把本机工作流推上去。

这和 Kimi 的浏览器工具不一样。Kimi WebBridge 寄生在你日常的 Chrome 或 Edge 上，只有那一扇浏览器里当前登着的号，每一步点击仍是 Agent 的一次工具调用。BrowserPilot 可以同时留下同一个网站的多套号，发文章时 Agent 只调用一次 `workflow_run`。

### 运行

专门一个工具：`workflow_run`。Agent 一轮里只调用它一次，传入工作流名称和 `inputs`。整张图都在这次调用里跑完，工具返回后 Agent 才看到结果。中间的点击和输入不是新的工具调用。

```ts
workflow_run({
  name: '公众号发文章',
  inputs: {
    标题: '九月更新',
    正文: '...',
    封面: 'C:\\covers\\sept.png'
  }
})
```

`name` 用保存时的名称。同名时用 `wf-` 编号。传了 `tab-` 就在那个标签里跑，所有窗口都能找到，不必再传 `env`。不传标签时，用 `env` 决定窗口，没传 `env` 就是 `env-default`；窗口里已有网页标签就用它，没有就新开一个。窗口当时没开，就先打开再跑。编号对不上就失败，不另开标签。

主进程从开始节点顺着边走，不是把节点重新登记成 `page_click` / `page_type` 交给模型：

1. 开始节点声明了必填输入而这次没给，就失败，一个节点都不做。
2. `goto` 用 `loadURL`。加载完成只说明文档到了，单页应用的界面可能还没渲染，不能据此做下一个节点。`if-else` 按条件选一条边。失败时返回停住的节点编号。
3. 点击、输入、粘贴、选择、滚动、滑动前先定位。写了 `xpath` 就用 `DOM.performSearch`，写了 `selector` 就用 `DOM.querySelectorAll`。两段字符串都原样交给浏览器。必须恰好一个。匹配到多个就停在这个节点，不取第一条。找到之后按节点的 `via` 执行。元素有一部分在画面外时，先把它滚进画面，再点能命中的位置。点击节点写了 `x` 和 `y` 时，点的是视口里的这个坐标，用来点画布；带了 `shotWidth` 和 `shotHeight` 就先按截图像素换算。没写 `via` 就是 `cdp`。`native` 走 `sendInputEvent`，`inject` 才在页面里执行脚本。上传仍是把本机路径交给文件控件。元素还没有时，在 10 秒内重试。滚动写了 `until` 时，会一直滚到那个元素能被点到，最多 16 次。点击写了 `until` 时，点完要看到那个元素，没看到就再点，最多 3 次。超时或点不到时，错误里带上匹配个数、文字和当时能不能点到。点击或页面脚本如果引起了加载，这个节点会等加载停下来再走下一条边。
4. `handoff` 去掉遮罩，窗口留下这句提醒，`control` 为 `handoff`。下一条边只连着一个带定位的节点时，那个元素出现后重新盖上遮罩，再继续。
5. 走到结束节点，或没有下一条边，才把结果作为这一次工具调用的返回值。成功时带 `files` 和结束节点收集的 `outputs`。失败时带节点编号。
6. `http-request`、`extract`、`script`、`code`、`loop`、`export` 按上面的产出写进变量池，后面的节点用选择器来取。`export` 的 CSV 放在本机 `exports`。点击、填写、选择按节点上的 `via` 走 CDP、原生或注入。滚动、滑动、按键没写 `via` 时走 CDP。
7. 同一次调用结束时，把结果写进这次运行记录：成功或停在哪个节点、当时的页面标题。失败时附一张截图路径。记录留在本机。若这个标签开着抓包，这一次运行期间的请求也收在同一次记录里。

页面改版导致「发表」按钮不再叫这个名字时，运行停在那个节点。Agent 再用普通工具确认新的定位，然后用 `workflow_write` 覆盖这张图。运行本身不临时改图。

### 批量

`workflow_batch`：

```ts
{
  workflow: 'wf-...',
  rows: [
    { 单号: 'A10086' },
    { 单号: 'A10087' }
  ],
  concurrency?: 1
}
```

每一行是一次独立运行，行与行之间不共享变量池。默认 `concurrency` 为 1，在调用方给的那个标签上排队。并发大于 1 时，多出来的行在同一扇窗口里各开一个新标签，所以已登录的 Cookie 还在。并发上限由设置封顶，默认最多 3。

一行失败不影响后面的行。返回值按行给：`ok`、`error`、停在哪个节点。同一次 `workflow_batch` 的行都在同一套环境里，用来对一个账号跑多条数据。

多个账号时，每个账号留在自己的一套环境里。这些环境都是人有头建好并登录过的。Agent 先 `env_list`，再对每个 `env-` 用无头方式 `env_open`，然后调用一次 `workflow_run` 或 `workflow_batch`。同一张图不用改，登录不用重登。这一套的 Cookie 不会进到另一套。要看着某一套做，就用有头把它打开。

命令行同一条工具，行很多时用 `browserpilot call workflow_batch --json-file rows.json`。

## 抓包

抓的是这个标签里 Chromium 已经解密的 HTTP(S)，不是网卡上的原始包。默认关闭。用户或 Agent 对某个 `tab-` 打开后才记录。

实现放在 `NetService`。打开时对该视图 `debugger.attach`，启用 CDP 的 `Network`，听 `requestWillBeSent` 和 `responseReceived`。正文用 `Network.getResponseBody`，只拉文本和 JSON，单条正文超过 1 MB 就丢掉正文、保留头和 URL。关掉抓包时 `detach`。

内存里每个标签保留最近 500 条。一条记录：

```ts
type Capture = {
  id: string          // req-
  tabId: string
  method: string
  url: string
  status?: number
  resourceType: string
  requestHeaders: Record<string, string>
  responseHeaders?: Record<string, string>
  mimeType?: string
  body?: string
}
```

工具：

| 工具 | 作用 |
|---|---|
| `net_start` | `{ tabId }` 开始记 |
| `net_stop` | `{ tabId }` 停止并 detach |
| `net_list` | `{ tabId, urlContains? }` 列出摘要，不含正文 |
| `net_get` | `{ reqId }` 返回这一条，含正文（若留着） |
| `net_export` | `{ tabId }` 写成一个 HAR 文件，返回路径 |

请求头里会有 Cookie 和 Authorization。记录只留在本机，工具描述里写明这一点。界面上的抓包面板和 `net_list` 用的是同一份数据。

## 能力都是工具

网页视图上的能力只通过工具暴露给 Agent，不另开一条私有通道。

`webContents` 能直接做的，各有一个具名工具：导航、点击、输入、粘贴、选择、按键、滚动、滑动、上传、截图、读取 Cookie 所属站点用的那些查询，都在 `tool-catalog.ts` 里。在页面里执行一段 JavaScript 只有 `page_script`。

每个工具的返回都带 `control`：`agent`、`shared` 或 `handoff`。用户点了「接管」之后是 `shared`。一次回放中途被接管时，另带 `takenOver: true`。

其余 CDP 不逐条起名。`page_cdp` 接收 `method` 和 `params`，主进程对当前标签 `debugger.attach`，发送这一条，取回结果后 `detach`。例如还没有单独工具的 `Emulation`、`DOM`、`Page` 方法走这里。已经有具名工具的动作，Agent 仍调用具名工具，不改走 `page_cdp`。

## 第一版工具

临时操作和录制、抓包都在 `tool-catalog.ts`。

带 `tabId` 的工具都按这个编号在所有窗口里找标签。找到了就操作那一页，不必再传 `env`。没传 `tabId` 时，才落到调用里的 `env`，都没有则用 `env-default` 里当前的网页标签。编号不存在就失败。

| 工具 | 作用 |
|---|---|
| `env_list` | 列出 `env-`、名称、备注、窗口是否开着、有头还是无头，并标明默认的那一套 |
| `env_create` | `{ name, remark? }` 新建一套空环境，分配编号，并在同一进程里打开一扇有头窗口 |
| `env_open` | `{ env, headless? }` 打开这套已有的窗口。人打开时是有头。Agent 批量时可传 `headless: true`。已经开着就按这次的显示方式切换，不另开一扇 |
| `env_update` | `{ env, name?, remark? }` 改名称或备注。编号不变。默认那套也能改 |
| `env_delete` | `{ env }` 关掉它的窗口，并清掉这一套分区。`env-default` 不能删 |
| `tab_list` | 列出全部窗口里的 `tab-`、所属 `env-`、所属 `grp-`、标题、URL |
| `tab_open` | `{ url, env? }`。不传 `env` 就在 `env-default` 的窗口里新开标签，返回全局唯一的 `tab-` |
| `tab_close` | `{ tabId }` 关掉这个标签。按编号在所有窗口里找 |
| `tab_activate` | `{ tabId }` 切到前台。按编号在所有窗口里找 |
| `group_create` | `{ name, color? }` 新建一组，返回 `grp-` |
| `group_update` | `{ groupId, name?, color? }` 改名称或颜色。编号不变，里面的标签还在 |
| `group_list` | 列出分组和里面的 `tab-` |
| `tab_group` | `{ tabId, groupId }` 把标签放进一组。`groupId` 为空则移出分组 |
| `page_navigate` / `page_back` / `page_forward` / `page_reload` | 导航 |
| `page_snapshot` | 当前标签的无障碍树 |
| `page_query` | `{ tabId?, xpath?, selector? }`。同一种定位的全部匹配，返回数组。点击不用这个结果去挑一个 |
| `page_click` | `{ tabId?, xpath?, selector?, x?, y?, shotWidth?, shotHeight?, via?, untilXpath?, untilSelector? }`。`via` 为 `cdp`（默认）、`native` 或 `inject`。元素必须恰好匹配一个。画布用 `x` 和 `y`，带上截图宽高时按那张图的像素换算。`until` 是按元素点完后要出现的元素 |
| `page_type` / `page_paste` / `page_select` | 同样用 `xpath` 或 `selector`，并带 `via` |
| `page_scroll` / `page_swipe` | 定位可省略，省略时从视口中心动手。`via` 为 `cdp`（默认）或 `native`。翻长列表用滚动，滑动是拖拽。`untilXpath` 或 `untilSelector` 表示做到该元素能被点到 |
| `page_upload` | 定位可省略，省略时用第一个文件控件。CDP 把本机路径交给文件控件 |
| `page_lock` | 锁定当前网页标签。遮罩正中是「Agent 正在操作浏览器」，下面是「接管」 |
| `page_unlock` | Agent 自己去掉遮罩。用户可以操作，任务不暂停，之后与用户同时操作 |
| `page_handoff` | `{ tabId?, message }`。放开页面让用户完成这一步。用户做完、下一步目标出现后，重新锁定并继续 |
| `page_key` | `{ tabId?, shortcut, via? }`。`via` 为 `cdp`（默认）或 `native`。把快捷键送进网页，例如 `Ctrl+A`、`Ctrl+Enter`。不触发窗口自己的新建标签、关闭标签 |
| `page_screenshot` | `capturePage`，返回图片路径和像素宽高 |
| `screen_start` | `{ env? }` 开始录这扇有头窗口 |
| `screen_stop` | `{ env? }` 停止并写成 `.mp4`，返回本机路径 |
| `page_source` | `{ tabId?, kind? }`。`dom`（默认）返回当前文档，`response` 返回这次导航的原始 HTML。不注入脚本 |
| `page_script` | `{ tabId?, source }`。在当前网页里执行这段 JavaScript，返回结果 |
| `page_cdp` | `{ tabId?, method, params? }`。调用一条 CDP。Electron 对这个网页视图还能做、但没有单独工具的能力，都从这里走 |
| `workflow_write` | 提交整张图。同名再次写入覆盖图，编号不变 |
| `workflow_update` | 按节点编号替换、追加或删除。没写到的部分保持原样 |
| `workflow_list` | 列出 `wf-`、名称、参数名 |
| `workflow_run` | 只传工作流名称和输入。内部跑完整张图，返回前不再向 Agent 要下一次工具调用 |
| `workflow_batch` | 多行输入，每行内部仍是一次整图运行 |
| `workflow_export` | 把这张图写成 JSON 文件，返回本机路径 |
| `workflow_import` | 从本机 JSON 文件导入。同名覆盖，编号不变 |
| `net_start` / `net_stop` / `net_list` / `net_get` / `net_export` | 抓包 |

密码和滑动验证码由 Agent 用 `page_handoff` 交给用户，这一步可以写进脚本。遮罩去掉，下一步的目标出现后重新锁定，Agent 继续后面的步骤。用户点「接管」或 Agent 调用 `page_unlock` 时，任务不暂停，之后人和 Agent 同时操作。

## 和 Kimi 浏览器工具的差异

Kimi WebBridge 是装在 Chrome 或 Edge 上的扩展，用 CDP 操作你正在用的那一扇浏览器。登录态直接拿日常浏览器里的，适合临时让 Agent 点几下。它没有「命名脚本 + 一次调用跑完 + 按参数批量」，也没有和这次运行绑在一起的请求记录。

BrowserPilot 只多做这三件，其余浏览器能力不拿来对标：

| | Kimi WebBridge | BrowserPilot |
|---|---|---|
| 浏览器 | 你日常的 Chrome / Edge | 同一个应用里的多扇窗口 |
| 登录态 | 寄生现成的那一个浏览器 | 多套环境，一套里多个网站；同一网站要多个账号就再开一套 |
| 重复操作 | 每次仍由 Agent 逐步调用工具 | `workflow_run` 一次跑完已保存的工作流 |
| 失败之后 | 靠下一轮对话再看 | 运行记录里有停在哪一步、截图，以及这次的请求 |

不做成第二个 WebBridge，也不把 Agent 的逐步点击换成他们的扩展。

## 验收

验收看一整段复杂操作能不能在一次 `workflow_run` 里做完，不看单个点击。下面三件都要在已登录的环境里通过。点击、输入、粘贴、选择默认走 CDP 可信输入。需要 `sendInputEvent` 时写 `via: 'native'`，需要在被挡住的节点上操作时写 `via: 'inject'`。

1. 自动滑动。打开一条信息流，按记下的方向连续滑动，直到出现指定的条目并点开。
2. 自动发文章。一次调用传入标题、正文和封面。封面按这条脚本的步骤来：上传就传本机路径，填链接就传 URL。输入标题，粘贴正文，放上封面，选择分类，滑到发布按钮并点击。页面是后来渲染出来的也要等到目标出现再点。返回成功，或停在哪一步。
3. 上传文件。把本机一个文件交给页面上的文件控件，页面上能看到该文件名。不弹出系统选择框。

每件失败时，运行记录里要有步骤序号和截图。

## 先做的范围

先做默认环境、从菜单或设置新建有头窗口（仍是同一个进程）、Agent 对已有环境无头打开、窗口上可复制环境编号、右键标签可复制标签信息、标签编号全局唯一、标签可在顶部或左侧、窗口录屏、一扇窗口里的标签都用这一套、标签分组，以及点击、粘贴、输入、选择、滚动、滑动、上传、截图。这些动作能串成一次 `workflow_run`。页面上不打自动化标记。验收按上一节的三件流程。不做指纹引擎，不为每套环境再启动一份应用，不做网卡级抓包。
